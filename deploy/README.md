# Vibe Island — production

Адрес: https://vibeisland.fun
Сервер: 92.118.169.204 (Ubuntu 24.04).

Российская версия: https://ru.vibeisland.fun — 170.168.112.169 (Ubuntu 24.04). Одинаковая сборка на двух независимых серверах. В настройках → Экран есть ссылки на обе версии. GeoDNS и автоматического перенаправления нет. Все музыка, звуки, обычные и 4K-пейзажи загружаются с выбранного сервера.

На российском сервере те же пути приложения и данных; nginx-конфиг и каталог сертификата называются `ru.vibeisland.fun`. Статистика и плейлисты хранятся отдельно на каждом сервере. Для статистики выполнить указанные ниже команды по SSH на каждом хосте; число посещений можно сложить, уникальных пользователей между адресами эти счётчики не дедуплицируют.

## Устройство выпуска

- Приложение: `/opt/vibe-island/current` → `/opt/vibe-island/releases/20260913-nature-mirror`.
- Node.js 24: `/opt/node24/bin/node`. Минимальные runtime-зависимости закреплены в `deploy/runtime/package-lock.json`.
- systemd: `vibe-island.service`, пользователь `vibe-island`, порт `127.0.0.1:4173`, автоматический запуск и перезапуск при сбое.
- Данные: `/var/lib/vibe-island/quiet-height.sqlite` и WAL-файлы. Новые релизы не должны заменять этот каталог.
- nginx: `/etc/nginx/sites-available/vibeisland.fun`, раздаёт статические файлы и проксирует `/api/`; HTTP перенаправляется на HTTPS.
- TLS: Let's Encrypt, `/etc/letsencrypt/live/vibeisland.fun/`, автоматическое продление через `certbot.timer`. Исходный `vibeisland.nginx.conf` — HTTP-шаблон для первого выпуска, повторно поверх HTTPS-конфига его не копировать.
- Плейлисты изолированы по браузерам (`PUBLIC_SITE=1`), без аккаунтов, через защищённую HttpOnly cookie. После удаления cookie прежний плейлист этому браузеру недоступен. Локальный режим без PUBLIC_SITE сохраняет прежнюю общую библиотеку.
- Загрузка файлов отключена в UI и API. Существовавшие локальные файлы не удаляются.
- Access log nginx отключён: статистика сохраняет приблизительные регионы, без сырых IP. Error log используется для диагностики.

## Команды на сервере

```sh
systemctl status vibe-island nginx
journalctl -u vibe-island -n 50 --no-pager
DATA_DIR=/var/lib/vibe-island /opt/node24/bin/node /opt/vibe-island/current/scripts/stats.mjs 30
systemctl list-timers certbot.timer
certbot renew --dry-run
```

Счётчики production начаты заново: локальная тестовая статистика не переносилась. Рабочие данные хранятся только в `/var/lib/vibe-island`.

## Обновление

Локально выполнить `npm ci`, проверки и `npm run build`. `node scripts/prepare-release.mjs` подготовит временную папку с готовой сборкой, сервером, справочником городов и минимальными зависимостями. Упаковать её (на macOS использовать `tar --no-xattrs --disable-copyfile`) и перенести на сервер. Секреты, `.git`, локальную `data/` и macOS `node_modules` в выпуск не включать.

Распаковать в **новый** каталог `/opt/vibe-island/releases/<дата-время>`, выполнить там `PATH=/opt/node24/bin:$PATH npm ci --omit=dev --ignore-scripts`, дать root владение и права чтения сервису. Сохранить путь прежней ссылки `readlink /opt/vibe-island/current`. Переключить `current` атомарно через временную символическую ссылку и `mv -Tf`, затем `systemctl restart vibe-island`. Проверить `/api/health`, воспроизведение MP3, картинки и сохранение своего плейлиста. nginx перезагружать только при изменении его конфигурации и после `nginx -t`.

Если health не отвечает или основной сценарий сломан, вернуть `current` на предыдущий релиз тем же способом и перезапустить сервис. Базу данных при откате приложения не заменять. Перед изменением её схемы сделать согласованную SQLite-копию; обычное копирование только `.sqlite` при работающем WAL недостаточно. До первого следующего обновления предыдущего релиза нет.

Сертификат и приватный ключ остаются на сервере; не включать их в проект или релизный архив. Для резервной копии данных остановить сервис, скопировать весь каталог `/var/lib/vibe-island`, затем запустить сервис.

## Отчёты о проблемах с экраном
В «Атмосфера → Экран и пейзаж» посетитель может одним нажатием отправить технический отчёт. `POST /api/device-report` сохраняет в `device_reports` браузер, экран/viewport/масштаб, поддержку fullscreen и выбранные настройки. Координаты, IP, cookies, снимок и введённый текст не сохраняются в отчёте. Чтения через публичный API нет. Повторы с тем же UUID не создают дубликат; ограничение — 5 отправок в минуту с адреса.

Последние 20 отчётов на сервере:
```sh
cd /opt/vibe-island/current
DATA_DIR=/var/lib/vibe-island /opt/node24/bin/node scripts/reports.mjs 20
```

Основной экран ограничен фактической высотой viewport. По умолчанию картина показывается целиком (`contain`); пользователь может сохранить режим заполнения. При скрытии интерфейса запрашивается полный экран, включая vendor API старых ТВ. Панель браузера может остаться, если устройство запрещает fullscreen. Проверены геометрия 320×568, 390×844, 800×450, 960×540, 1280×720, 1920×1080, отправка отчёта, переключатель масштаба и таймер в Chromium. Реальный ТВ требует проверки владельцем.

### Нейтральные поля (13 сентября, исправление для ТВ)
Отчёт Haier Android TV / Яндекс TV показал viewport 960×540, DPR 2, fullscreen и fit=cover. Он не содержал геометрию canvas, поэтому происхождение боковых полос на устройстве не подтверждено. Убраны постоянный синий градиент, синий фон полей и синий theme-color; в zen затемнение полностью исчезает. Новые отчёты display-20260913-2 дополнительно сохраняют прямоугольники сцены/canvas и размер буфера для диагностики WebView. Проверены чёрный фон, нейтральный градиент, нулевая opacity затемнения в zen и отсутствие прокрутки при 960×540 в Chromium.


### Исправление масштаба на ноутбуке
По отчёту 1470×891 canvas занимал весь viewport, но сохранённый contain оставлял полосы. Теперь по умолчанию cover; новая версия ключа quiet-height-fit-v2 сбрасывает старый стандартный contain один раз. Явный новый выбор сохраняется. Смена fit мгновенная, независимо от 12-секундной погодной анимации. В contain свободная область заполняется приглушённой размытой копией текущей сцены, чтобы под управлением не было сплошных полос. Проверены реальные переключения cover → contain → cover и снимок cover при размере ноутбука 1470×891.

### Телефон, ТВ-настройки и музыка
Мобильные элементы компактнее, погода — 2 ряда по 5 кнопок, плеер полупрозрачный с blur. Учтены safe-area и визуальный viewport. Настройки разделены на Пейзаж / Звуки / Фокус / Экран, прокрутка внутри содержимого, навигация разделов закреплена. Кнопка таймера сразу открывает Фокус. При отказе Fullscreen API включается zen без мешающего toast. Для iOS добавлены метатеги standalone и инструкция добавления на Домой; реальное устройство iOS не тестировалось. Shuffle по умолчанию true, repeat плейлиста false. Chromium: 390×700, 960×540, четыре раздела, запуск/отмена таймера, смена треков; build/lint/TypeScript и 15 тестов прошли.

### Возврат единого пейзажа и отдельный микшер
Режим contain и размытая подложка удалены по просьбе владельца: один пейзаж cover при любых старых localStorage-настройках. Кнопка «Белый шум» рядом с таймером открывает отдельную панель NoiseMixer. Микшер и вкладка Звуки удалены из Атмосферы, сам useNoiseMixer остаётся смонтирован при закрытии панели. Проверены открытие новой панели и отсутствие прежней вкладки, размеры 390×700 и 1470×891 без прокрутки, четыре звуковых теста, TypeScript/lint/build.

### 4K-пейзажи
Все 9 оригиналов сохранены в public/scenes. Версии 3840×2160 в public/scenes/uhd восстановлены локальным Real-ESRGAN x4plus, затем уменьшены с 6688×3764 до 4K и сжаты WebP q92. Это AI-реставрация, не нативная съёмка 4K. Процесс и ограничения описаны в public/scenes/uhd/README.md; скрипты scripts/upscale-scenes.sh и scripts/verify-uhd.mjs; manifest.json содержит размеры и SHA-256 исходников и результатов.
В Атмосфера → Экран добавлен выбор Авто / HD / 4K. Авто загружает улучшенный исходник для рендера длиннее 1672 пикселей, HD — исходный. Режим 4K задаёт буфер до 3840×2160 для 16:9 даже на ТВ с логическим viewport 960×540. Максимум 8.3 Мп и 3840 по стороне, кэш двух сцен; при ошибке загрузки UHD используется оригинал. ОС телевизора может выводить WebView в 1080p, сайт не управляет физическим видеорежимом. В диагностику добавлены выбранное качество и разрешение загруженного исходника.

Выпуск 4K: все 9 UHD-файлов проверены 3840×2160, суммарно 12.3 MiB. Проверены build/lint/TypeScript и 17 тестов; в браузере источник 3840×2160 и буфер 3840×2160 на viewport 960×540, HD/fallback к 1672×941. Предыдущий выпуск 20260913-single сохранён для отката.

### Навигация белого шума
Кнопка «Плейлисты» в плеере заменена на «Белый шум»; она открывает Атмосфера → Белый шум. Нижний дубликат и отдельная панель удалены. Микшер снова расположен в отдельном разделе настроек. Музыкальная библиотека доступна по нажатию на название текущего трека. Кнопка плеера доступна также при мобильной и компактной ТВ-компоновке. Проверены build/lint/TypeScript, открытие нужного раздела на 1470×891, 390×700 и 960×540.
